# W10 · 演示视频脚本

> **计划要求**：README + 一页纸 + 演示视频。**Agent 演示必须进视频** —— 它是头号卖点,
> 而初筛阶段评委可能只看视频。
>
> **目标时长 2:00**。初筛评委的耐心约等于这个数；超过 2:30 完成率会明显下降。
> 每一段都标了「砍掉哪一段」的兜底，实在超时按顺序砍。

---

## 录制前必须先做完的三件事

| # | 事 | 为什么 |
|---|---|---|
| 1 | **往 `shared/agentAddresses.json` 填一个 agent 地址** | 否则第 6 段那个 `[Agent]` 徽章**不亮** —— 而那段是整条视频的落点。脚本自检时会把你该粘的那行直接打出来 |
| 2 | **准备三个不同地址**：创作者 / 人类买家 / agent | §16.1 第 7 条要求人类那一笔和 agent 那一笔落在**同一个创作者、同一页看板**上，否则"分账比例一致"没有对照组 |
| 3 | **两个地址都要有 Fuji USDC + AVAX** | Circle faucet 限 1 USDC / 2 小时 / 地址；AVAX 去 Core faucet。现场翻车 90% 是卡在这里 |

> ⚠️ **顺序不能换**：必须**人类先买、agent 后买**。反过来也能出徽章，
> 但那时看板上只有 agent 一笔，没法当场对比 —— 而对比正是要验的东西。

## 分镜表

### 1 · 0:00–0:06 ｜ 一句话定位

**画面**：浏览器打开 `https://splitjar.vercel.app`（角色分流落地页，三栏）。

**口播**：
> SplitJar 收钱罐。创作者定好价格和分账比例，上传内容，拿到一个付费页。
> 买家付稳定币，钱按比例**当场直达**各方钱包 —— 没有平台抽成，没有资金池。
> 同一套付费墙服务两类买家：人类连钱包付，AI Agent 走 HTTP 402 自己付。

---

### 2 · 0:06–0:18 ｜ 创作者：定价 + 三方分账

**画面**：`/console` → 「发布新内容」→ 填标题、价格 `0.2 USDC`、三个收款方 70/20/10
（**合计实时校验 = 100%**）→ 选文件 → 等派生预览图出来。

**口播**：
> 创作者这边：定价 0.2 USDC，分给三个人 —— 70、20、10，合计必须等于 100%，
> 余数归属规则和合约逐字一致。
> 这张预览图是浏览器本地生成的，原图不会离开这台机器；但它会公开在广场上，
> 所以水印是真打上去的，不是显示效果。

**屏幕上要能看清**：70/20/10 那三行、合计 100%、预览图那句「公开」的黄字提示。

---

### 3 · 0:18–0:32 ｜ 人类买家：连钱包付两笔，立刻解锁

**画面**：复制付费页链接 → 换一个浏览器/隐身窗口打开 `/p/:id` → 连钱包 →
`approve` → `pay` → 状态机走完 → 点下载。

**口播**：
> 买家打开这个链接，连钱包，两笔交易：`approve` 授权 USDC，然后 `pay`。
> 付完立刻解锁，拿到的是 60 秒短时效的下载链接。

**⚠️ 别剪掉等待**：状态机中间那几秒（签名中 / 上链中 / 确认中）**保留**。
那正是"每种失败都有明确界面状态"的证据，剪掉就只剩一个成功动画，看不出设计。

---

### 4 · 0:32–0:36 ｜ 看板出现第一笔

**画面**：创作者打开 `/dashboard`，那一笔出现了，分账明细三行。

**口播**：
> 看板这一屏是**直接读链上 `PaymentSplit` 事件**渲染的，没有我们自己的数据库。

---

### 5 · 0:36–1:08 ｜ **Agent 全程（视频的重心）**

**画面**：终端全屏，字号调大（**至少 16px**，评委可能在手机上横屏看）。
跑 `BASE_URL=https://splitjar.vercel.app node scripts/agent-buy.mjs`。

**口播**：
> 现在换成 AI Agent —— 一个脚本，没有任何人在旁边点。
>
> 第一步，它自己去 `/api/catalog` 发现可售内容，**买哪一件由它自己挑**，不是我指定的。
> 第二步，它请求内容，拿到 **402** 和一份 HMAC 签过名的报价。
> 第三步，它自己发两笔交易 —— `approve` 加 `pay`，**和人类走的是同一个合约函数**。
> 第四步，它把交易哈希回传，换回下载链接，下载完**自己比对 `keccak256`**。
>
> 每个关键值都标了来源：金额只认 402 报价里的 `accepts[0]`，付款人由私钥推导再回链核对。

**屏幕上要能看清**：402 那几个字段（`accepts[0]` / `maxAmountRequired` / `quoteId`）、
最后那行「哈希一致」。

> ⚠️ **这一段是全片最重要的 30 秒，别加速、别剪成快进。**
> 建议先跑一次 `--dry-run` 录一遍（一分钱不花），确认画面清楚再真跑。

---

### 6 · 1:08–1:22 ｜ **看板对照（落点）**

**画面**：回到 `/dashboard`，同一件内容下面**并排两笔**，第二笔带 `[Agent]` 徽章。
鼠标划过两笔的分账明细。

**口播**：
> 回到看板：同一件内容下面现在并排两笔。
> 上面这笔来自人类地址，下面这笔来自 agent —— 带 `[Agent]` 徽章。
> **两笔的分账明细格式与比例完全一样**，都是 70、20、10。
> 这就是要证明的事：机器和人走的是同一条结算路径。

**屏幕上要能看清**：`[Agent]` 徽章、**两组分账数字完全相同**。

> ⚠️ 这一段必须给**两秒静止**让人看清数字。

---

### 7 · 1:22–1:34 ｜ 链上当场验证

**画面**：从 agent 那笔点进 Snowtrace，展示 `PaymentSplit` 事件与三个收款方的转账。

**口播**：
> 这笔在区块浏览器上可以当场验证：`PaymentSplit` 事件里三个收款方的金额，
> 和界面上显示的一致。链上 5 笔付款都验过。

---

### 8 · 1:34–1:52 ｜ 诚实边界（**别省，这是加分项不是扣分项**）

**画面**：切到一页纸里那张对照表（或 README 那一段）。

**口播**：
> 最后说清楚我们不做什么。
>
> 我们**复用 x402 的形态，没有实现 x402**。报价字段和命名都照它来，
> 但信任模型正好相反：x402 的支付头装的是**还没广播的签名授权**，
> 我们装的是**已经广播的交易哈希**，只去链上查证。
> 更关键的是，x402 的 `exact` 方案**只有一个收款人**，
> 装不下"同一笔付款分给 N 个人" —— 而那正是这个产品的核心。
>
> 另外两条：Agent 路径**没有 reorg 保护**，判据是确定性而不是确认数，上主网必须改；
> `[Agent]` 徽章是**地址白名单**判定的，链上分不出人和机器，我们不会含糊地说"能识别"。

## 三个最容易翻车的点

| 点 | 症状 | 预防 |
|---|---|---|
| `agentAddresses.json` 是空的 | `[Agent]` 徽章不亮，第 6 段落空 | 开录前先跑一次 `agent-buy.mjs --dry-run`，脚本自检会把该粘的那行打出来 |
| 人类先买 / agent 后买的顺序反了 | 看板上只有 agent 一笔，没法对比 | 严格按 3 → 5 的顺序 |
| 终端字号太小 | Agent 那段在手机上糊成一团 | 录前把终端拉到全屏 + 字号 16px 以上，录完自己用手机横屏看一遍 |
