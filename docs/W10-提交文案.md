## Full Description *（必填，详细描述）

> 纯文本排版，不依赖 markdown 渲染；粘进去行距和缩进都能读。

```
【一句话】
创作者付费内容 + 链上多方分账。人类连钱包付，AI Agent 走 HTTP 402 自助付。

【解决的问题】
平台代卖抽成 10–30%、提现周期长；协作分账靠人工转账、要互信；内容要给 AI Agent 用时，没有为机器设计的付费入口——Agent 不会扫码、不会填表、不会注册账号。Agent 经济缺的不是支付网络，是"机器能自己完成的付款流程"。

【怎么工作】
创作者定好价格与分账比例（最多 10 方，实时校验合计 = 100%，余数归属与合约逐字一致），上传内容，拿到付费页。
· 人类买家：扫码打开付费页(手机需 WalletConnect 或钱包 App 内置浏览器)→ 连钱包 → approve + pay → 内容立即解锁
· AI Agent：GET /api/catalog 自己发现 → 请求内容拿到 402 + HMAC 签名报价 → 自己发交易 → 回传 txHash → 换 60 秒短时效下载链接 → 自己比对文件哈希
两条路走的是同一个合约函数 pay(bytes32)，留下同一个 PaymentSplit 事件——不是两套系统长得像，是同一条结算路径的两种入口。

【核心特性】
· 一笔付款当场分给 N 方，钱不经平台、不留资金池；收款看板直接读链上 PaymentSplit 事件渲染，没有自己的数据库
· 收款方转账失败（如被代币方拉黑）时，份额记入 pendingBalance 由本人 withdraw() 取走，付款人不会被 DoS
· 内容存证：下载文件的 keccak256 == 链上 contentHash（实测 277,343 字节逐字节相同）
· 未付款拿不到内容：402 → 报价签名（防篡改）→ KV 短租约防重放 → 60 秒短时效 URL（实测 63 秒后 403）
· 内容广场 + 「一句话找内容」：自然语言 → 结构化筛选，LLM 失败时强制降级并如实说明，不假装能用

【技术实现】
前端 Vite + React 19 + Tailwind v4 + wagmi/viem；合约 Solidity + Foundry（CreatorSplitter，27 个单测全过：余数归属、重入、escrow 三分支）；服务端 Vercel Functions + Upstash Redis KV + Vercel Blob（内容走私有 store + 短时效签名 URL，预览图走公开 store）。

【为什么是 Avalanche】
· Fuji 有官方 Circle USDC，不用自己发测试币充当稳定币
· 亚秒级出块，付款后内容几乎立刻解锁——付费墙体验能不能成立的前提
· gas 极低：实测单笔分账钱包实付约 0.005 美元，占成交额（0.2 USDC）的 2.5%——小额付费在商业上成立

【已验证】
· 合约部署 Fuji 并逐项读链验证（字节码一致、USDC immutable 接对、不存在的 id revert 出 ContentNotFound）
· Agent 七项验收全绿：catalog 可列 / 402 报价字段完整 / 全链路无人干预 / txHash 可在区块浏览器当场验证（链上 5 笔）/ 同一 txHash 复用被拒 409 / 冒用他人 txHash 被拒 403 / 看板标 [Agent] 且分账比例与人类完全一致

【诚实边界（我们主动说）】
· 复用 x402 的形态与字段命名，但没有实现 x402：支付头装的是已广播交易的哈希，不是 EIP-3009 待广播授权，信任模型相反；且 x402 的 exact 方案只有单 payee，容纳不下一笔付款分给 N 方——而那正是本产品的核心
· Agent 路径没有 reorg 保护，判据是确定性而非确认数，上主网必须改成等确认数
· 门禁的信任面在 RPC；[Agent] 徽章是地址白名单判定，链上分不出人与机器，我们不含糊地说"能识别"
· 测试网作品，不涉及真实资金

【链接】
线上演示：https://splitjar.vercel.app
GitHub：https://github.com/emptytouch/splitjar
演示视频：（视频传好后填这里）
一页纸：https://github.com/emptytouch/splitjar/blob/main/docs/W10-%E4%B8%80%E9%A1%B5%E7%BA%B8.md
```
