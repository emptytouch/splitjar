## 〇、结论

`docs/开发计划.md` §W9 的目标只有一句话：

> **§16.1 的 Agent 七项验收全绿。**

**2026-09-25 判定：七项全部有可复跑的机器证据。** 见 §一。

**为什么可以这样结，而不是补一次"正式联调"：**

1. **W9 是检查点，不是交付物。** §17.3 把它列为关键检查点 —— 它要验的东西
   （402、链上校验、防重放、看板标注）**W7/W8 自己必须先做出来才能交付**。
   两个包各自验收时，验的就是 W9 要验的同一批东西。
2. **W7/W8 的验收被环境挤到了部署之后。** W7 期间本机被判定"发不出请求"
   （真因是没走代理，见 W8 文档 §十一），所以两包的线上验收集中在 09-24/09-25 做，
   **天然就是端到端的**——打的是生产、读的是真链。
3. **§17.3 的触发条件没有发生。** 那条写的是「若此时 Agent 路径未跑通 → 立即停止投入，
   回退纯人类路径」。**它跑通了**，所以：
   **不需要回退，`§1.2` / `§12.1` / `§13` 三节论证不需要改写。**
   （那是回退才要付的代价，这里明确记一笔省得以后有人以为漏了。）

## 一、七项逐条：判据 · 怎么复跑 · 实测

七项里 **五项**由 `scripts/verify-x402.mjs` 与 `scripts/check-7th.mjs` 覆盖，
**一项**（Agent 全链路）由 `scripts/agent-buy.mjs` 真跑覆盖，
**一项**（重放被拒）矩阵里是 skip 的，本文件用一条零成本手法单独补验（见 ⑤）。

| # | §16.1 原文 | 判据（脚本里的那一行） | 实测 |
|---|---|---|---|
| ① | `GET /api/catalog` 能列出可售内容与价格 | `verify-x402.mjs` 第 0 步 | ✅ 200 · 2 件 |
| ② | 未付款请求 `/api/content/:id` 返回 402 且**报价字段完整** | `verify-x402.mjs:397` | ✅ |

### ① catalog 可列

```bash
export HTTPS_PROXY=http://127.0.0.1:7897 HTTP_PROXY=http://127.0.0.1:7897
curl -s -w '\nHTTP=%{http_code}\n' https://splitjar.vercel.app/api/catalog
```

⚠️ **这一条要连 `title` 一起看**：`title` 来自 KV，而 `api/catalog.ts` 把读 KV 包在
try/catch 里 —— **KV 读不到时每条的 `title` 都变成 `null`，HTTP 照样 200**。
判据：**全表 `null` ⇒ KV 那条路不通**；只有个别 `null` ⇒ 那件真的没标题。
2026-09-25 实测两件都有标题（`苹果图` / `newTest`）⇒ KV 正常。

### ② 402 报价字段完整

```bash
BASE_URL=https://splitjar.vercel.app node --use-env-proxy scripts/verify-x402.mjs
```

断言在 `verify-x402.mjs:397`，判的是**四个 quote 字段一个不少**
（`contentId` / `quoteId` / `expiresAt` / `sig`）**外加** `x402Version === 1`、
`payTo` 是合约地址、`maxTimeoutSeconds === 900`。不是"看到 402 就算过"。

### ③ Agent 全链路无人干预

```bash
export AGENT_PRIVATE_KEY=0x…          # ⚠️ 只在当前 shell
BASE_URL=https://splitjar.vercel.app node --use-env-proxy scripts/agent-buy.mjs
```

八步：自检 → 发现 → 读 402 → 判额度 → **approve → pay** → 赎回 → 下载比哈希 → 结论。
**私钥只在用户自己的 shell 里**（方案 §6.2），所以这一段由**用户本人**执行，
agent 用的是专属地址 `0x0016486a…d0Cf`（`shared/agentAddresses.json`）。

⚠️ **反造假红线**：脚本里不许出现"价格"这类关键值的硬编码 —— 金额只认 402 响应里那个数。
别为了让输出好看去改这一步。

### ⑤ 同一个 txHash 第二次被拒（⚠️ 这条是本次补的）

**矩阵里这条是 `skip` 的。** `verify-x402.mjs` 把它和 200 happy path 捆在一个
`--burn` 分支里 —— 因为它验的是"**新鲜**付款先成功、再打一次得 409"，
而成功那一步会**永久**消耗掉那笔付款（KV 键**没有 TTL**）。用户没授权烧，
所以那次线上跑是 `14 通过 / 0 失败 / 3 跳过`，**④ 在跳过里**。

**零成本补验的办法：拿一笔"已经被消耗过"的付款去撞。** 它本来就已经兑不出来了，
撞它不会烧掉任何还没用过的凭证：

```js
// 1) GET /api/content/<已买过的 contentId>  → 402,顺手拿到一份**新报价**
//    ⚠️ 报价必须与请求路径对得上,否则会被第 ⑤ 条先挡成 quote_invalid
// 2) 带 X-Payment 头再打一次:
//    { txHash: <已消耗的那笔>, payer, quoteId, expiresAt, sig }
//    ⚠️ 五个字段**全是字符串** —— 402 体里的 expiresAt 是**数字**,
//       不 String() 会得到 400 bad_request(本次踩到)
```

2026-09-25 实测（用 agent 那笔已被 `agent-buy.mjs` 自己兑掉的 `0xdc55ab9e…`）：

```
→ HTTP 409  {"error":{"code":"payment_replayed","message":"这笔交易已经被用过了"}}
```

**第 ④ 条成立。** 矩阵那条仍然该保持 `--burn` 门禁 —— 它验的是另一件事
（新鲜付款的成功路径），两者不冲突。

### ⑥ 冒用他人 txHash

`verify-x402.mjs` 第 ③ 条：合法 `txHash` + **别人的** `payer` → `403 payment_mismatch`。
⚠️ 这条**不消耗**凭证（服务端在 `finally` 里 `releasePayment`），所以随便跑。

### ⑦ 看板标注 + 分账一致

```bash
HTTPS_PROXY=http://127.0.0.1:7897 node --use-env-proxy scripts/check-7th.mjs
```

**链上判，不靠截图**：新创作者 `0xAa05f680…0bba` 名下的苹果图下有
**人类一笔 + agent 一笔并排**，两笔的 `recipients` / `amounts` **完全一致**
（0.14 / 0.04 / 0.02），agent 那笔的 `payer` 在白名单里。三要素全 ✓。

> 并排之所以成立，是因为**演示顺序不能换**：人先买、agent 后买。
> 反过来，看板当场只剩 agent 一笔，没法对比。

## 三、没做到的（如实记录）

1. **"走一遍 UI"那部分没有逐屏记录。** 看板徽章是用户在浏览器里切钱包看到的，
   留档的是**链上判**（`check-7th.mjs`）。链上判比截图强，但"当场点一遍"这件事本身没有记录。
   若 W10 的视频要这一段，得**重新走一遍并录屏**。
2. **矩阵的 ⑩ / ⑦ 两条仍空着**，都是环境限制不是缺陷：
   ⑩ 缺一件已下架内容的 id（`X402_INACTIVE_ID`）；⑦ 要生产环境的 HMAC 密钥。
3. **③ 那一段的终端输出没有原样留档**（私钥在用户 shell 里，跑的时候我这边看不到）。
   本文件记的是它的**链上结果**（第 ④ 项的 5 笔）。
4. **第五笔之后的 `PaymentSplit` 依赖手动扫链**。`DEPLOY_BLOCK` 起的区间已经超过
   备份端点的 50k 上限，所以脚本是**分窗**扫的（`77ade90`）。

## 四、与上游的差异记录（追加，不覆盖原文）

1. **§W9 的排期是 9/27，实际 9/25 结。** 原因见 §〇：它不是被"做掉"的，
   是被 W7/W8 的验收吸收掉的，而那两个包的线上验收本来就压在部署之后。
2. **§W9「端到端联调」的字面意思是"联调一遍"。** 本文件把它结成了
   **"七项各自有可复跑证据"** —— 因为逐项证据比"我跑过一遍"更强（能重跑、能证伪）。
   ⚠️ 代价是 §三.1 那条：**UI 那一遍确实没录**。
3. **七项里 ⑤ 的验证路径与矩阵不同。** 矩阵走 `--burn`（新鲜付款 → 成功 → 重放），
   本文件走"已消耗的付款 → 重放"。**两者都成立且不冲突**，但**不能互相替代**：
   前者顺带验了 200 happy path，后者才是零成本的。
