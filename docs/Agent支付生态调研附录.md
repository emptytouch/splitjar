# Agent 支付生态调研（§22 依据）

> 用途：确认 x402 等 Agent 支付方案进展，明确"我们是内容侧不是支付侧"，避免与支付协议层撞车。调研日期 2026-09-21。
> 核心结论：支付侧（agent 支付协议/管道）已由 x402、Visa、Mastercard、Stripe、Google 完成标准化且成红海；我们定位"创作者内容变现 + 多方分账"应用层，互补不竞争。

---

## 一、支付侧生态全景（2026，已成红海）

| 协议 | 主导方 | 轨道 / 类型 | 主要合作方 | 主场景 | 状态 |
|---|---|---|---|---|---|
| **x402** | Coinbase → Linux Foundation | 稳定币（USDC） | Visa, Stripe, AWS, Anthropic, Google, Mastercard, Circle | API 微支付、按次调用（机器对机器） | Live，$600M+ 已处理 |
| MPP（Machine Payments Protocol） | Stripe + Tempo（Visa 设计伙伴） | 稳定币 + 法币 | Visa, Affirm, Klarna | agent-to-agent B2B、按量计费 | 2026-03 launch |
| Visa TAP / Intelligent Commerce | Visa | 法币（tokenized Visa） | OpenAI, Perplexity, Anthropic, Ant, Grab | 消费电商、B2B 账单 | GA 2026-06 |
| Mastercard Agent Pay | Mastercard | 法币（Agentic Token） | Microsoft, IBM, Braintree, Fiserv | 零售、银行、跨境 B2B | Q2 2026 GA |
| UCP + AP2 | Google | 支付无关（密码学 mandate） | Mastercard, Visa, PayPal, Adyen, Amex, Revolut | 全电商生命周期（发现→结账→售后） | 2026-01 announce |
| ACP（Agentic Commerce Protocol） | OpenAI + Stripe | 账户制 | Shopify 生态 | ChatGPT 内购物 | 已上线（4% 交易费） |
| MCP | Anthropic | 集成标准（非支付） | 各 PSP 已出 MCP server | agent 工具调用层 | 2024-11，已成事实标准 |
| 国内 | 蚂蚁（MCP→支付宝）、微信/银联 | 法币 | — | 智能体调支付宝全链路 | 2025-07 起 |

## 二、x402 进展（重点确认）

- 2025-05 Coinbase 联合 Cloudflare 发起，复用 HTTP 402 "Payment Required" 状态码，让 AI agent 用 USDC 自动付 API/数据费。
- 2026-04 转入 **Linux Foundation**（x402 Foundation），成员包括 Visa、Stripe、AWS、Anthropic、Google、Mastercard、Circle——**已成中性治理的事实标准**。
- 规模：累计 **1 亿+ 交易**，$600M+ 已处理；近期单月 ~7200 万笔、~$2400 万体量（Base + Solana）。
- 定位：机器对机器（M2M）微支付传输层，**不碰人类创作者变现/分账**。

## 三、我们的定位：内容侧，不是支付侧

- **支付侧（x402 / MPP / ACP / TAP …）**：解决"钱怎么在 agent 与系统之间自动、无账户地转移"——是协议层 / 结算 rail，已被巨头标准化，创业团队做这个=撞车自杀。
- **我们（收钱罐 CoinJar）**：解决"人类创作者如何把数字内容变成可收费、可多方分账、可链上存证的商品，并让人类粉丝扫码付"——是**应用层 / 内容变现层**。
- 赛道选择印证：我们 spec 主打 **02 支付 + 03 创作者经济**，**没打 04 身份/信任与 AI**，正是刻意避开 agent 支付协议的正面竞争。
- **细分空白**：现有生态全是"agent 付 API / 商家"（M2M、人或 agent 对商家），**没有人做"人类创作者对人类粉丝的链上多方分账 + 内容存证"**——我们填这个空。

## 四、与 x402 的关系：互补，不撞车

- x402 是我们的**潜在结算 rail，不是对手**。我们产品"用稳定币付"，x402 是其中一种底层传输方式。
- 一句话区分：**x402 解决"钱怎么自动转"，我们解决"内容怎么变成可收费 / 可分账 / 可存证的商品"。**
- 演进路径：v1 用标准钱包支付；v2 可接入 x402 / MPP 做底层 agent 友好结算，我们始终是上层应用。

## 五、评审防撞车 Q&A 预备

- **Q：你们和 x402 有什么区别？**
  A：x402 是机器对机器的支付管道（agent 调 API 自动付 USDC）；我们是人对人的内容变现 + 创作者多方分账工具。x402 关心"传输"，我们关心"内容商品化 + 收益分配 + 存证"。我们未来还能用 x402 做结算层。
- **Q：为什么不做 agent 支付协议？**
  A：该层 2026 年已被 x402（Linux Foundation）、Visa TAP、Mastercard Agent Pay、Stripe MPP、Google UCP 标准化且成红海，创业团队无优势。我们聚焦创作者经济的应用层空白。
- **Q：赛道 04（身份/AI）你们不打？**
  A：刻意不打。我们落 02+03，用"内容侧"差异化，不与 agent 支付基础设施正面冲突。

## 七、⚠️ 核实后更正（2026-09-21，由 Claude 复核）

生态全景的**定性判断基本正确**（支付侧已成红海、我们该做内容侧），但有一处**数量级错误**和**一处定位冲突**，另有一个**对本项目极有利的发现**被漏掉了。

### 7.1 ❌ 数量级错误：x402 的 "$600M+ 已处理" 不成立

| 口径 | 已核实数字 | 来源 |
|---|---|---|
| 累计交易笔数 | **1.096 亿笔**（自 2025-05） | Visa 报告（2026-04-21，引 Artemis Analytics） |
| **累计金额** | **$15.0M**（调整后） | 同上 |
| 近 30 天（2026-07） | **7500 万笔 / $24M**，均价 **~$0.32** | CoinDesk（2026-07-15） |

**$600M 与本附录自己写的"单月 ~$2400 万"自相矛盾** —— 7500 万笔 × $0.32 ≈ $24M，109.6M 笔累计金额按同口径应约 **$35M 量级**，而不是 $600M。**附录应是混淆了"交易笔数"与"金额"。**

**正确写法**：`累计 1 亿+ 笔，但累计金额仅约 $15–35M 量级；单笔均价约 $0.32`。

> **⚠️ 这个修正的含义比数字本身重要**：x402 是**笔数巨大、金额极小**的市场。这**恰好印证**微支付论证（单笔 $0.32 —— 卡费根本做不了），但也说明 **Agent 支付的真实资金体量目前仍很小**。写 README 时不要用"$600M 市场"这种话，**会被当场戳穿**。

### 7.2 ⚠️ 遗漏的关键保留意见：大量交易并非"Agent 买服务"

Chainalysis 指出：**2025 年末 x402 的交易量激增中，很大一部分是 meme 币活动，而非 Agent 在购买服务。**

**这必须写进 README 的诚实边界**：引用 x402 规模数据时，要说明"其中包含非 Agent 用途的活动"。**主动说明 = 你读过一手资料；被问出来 = 你只看了二手摘要。**

### 7.3 🔥 漏掉的最佳证据：Avalanche 是 x402 V2 的一等公民

**这是本附录最该有却没有的一条**：

- **x402 V2（2025-12-11）原生多链**：Base / Solana / **Avalanche**，用 CAIP-2 标识
- **明确支持 Avalanche 主网与 Fuji 测试网（chain ID 43114 / 43113）** —— **正是我们部署的链和测试网**
- 已有开源 SDK（`x402-rs` / `x402-go` / `x402-rails` 等）把 Avalanche 列为一等网络
- USDC 在 Avalanche 主网与 Fuji 均有部署

**为什么这条极重要**：我们 spec 的 [§12.3](splitjar-product-spec.md) 承认过一个短板——"未用到 Avalanche 独有原语，链选型是场景驱动而非生态内建"。**直接采用一个把 Avalanche 列为一等公民的行业标准，是目前能拿到的最强 Avalanche 契合证据。** 这比任何论证都实在。

**已执行**：`coinjar-product-spec.md` §9.4 已从"x402 **风格**的自研实现"调整为"**对齐 x402 V2**"，并记录了需要解决的设计问题（x402 的 ERC-3009 单 payee 转账 vs 我们合约内 N 方分账）。

### 7.4 🏆 意外收获：Visa 官方复述了我们的核心论证

Visa 在其 Agentic Payments 报告中的表述：

> **HTTP 402 "Payment Required" 状态码在 1990 年代就被预留，但闲置了三十年 —— 原因是"卡组织手续费让不足 1 美元的支付不经济"。**

**这几乎是 spec §12.1 论证的官方版本。** 已补入 spec §12.2.1 第 4 条，建议 README 直接引用并标注来源——**这是全篇最有分量的外部背书**。
